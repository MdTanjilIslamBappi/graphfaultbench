# Reproducibility guide (Checkpoint 3)

## What can be reproduced from this release

This release omits every per-task output file (`metrics.csv`, `rankings.jsonl`, `calls.jsonl`, `raw_outputs.json`, `gold_resolution_reports.json`, `graph_reports.json`, gold-hidden rows, commit mappings), because they carry Loc-Bench V1 task identifiers, gold-derived hit flags or dataset-derived commit mappings and the dataset's redistribution terms are unstated (`LICENSES_AND_DATA_ACCESS.md`). **None of the empirical results in the paper has been regenerated from raw inputs for this release.**

**A. Reproducible from public artefacts alone**
- Unit tests: `uv run pytest -q` (68 tests, synthetic and toy inputs only) and `uv run ruff check .`.
- Synthetic framework validation: `uv run python experiments/pilot_a/run_framework_validation.py`. Its outputs in `results/framework_validation/` were regenerated byte-identically in a clean environment. This validates the harness on synthetic graphs; it is not evidence about Loc-Bench results.
- Reading the stored aggregates: `results/analysis/*.json`, per-run `summary.json` and `run_manifest.json`, `results/gemma_v2/{summary,audit,run_manifest}.json`, `results/repomap_correction/*/run_manifest.json`. These are as-run records and are not recomputed.

**B. Reproducible only with separately obtained data**
- Loc-Bench V1 (`czlll/Loc-Bench_V1`, 560 rows, parquet sha256 `8df0833c2c1276c5837aab923d489ab97d7654529abe759d0f59242c4978a662`), the commit-pinned repository snapshots, and, for the Gemma experiment, the Gemma 4 E2B GGUF (`manifests/gemma4_manifest.json`).
- With these, the experiment runners under `experiments/pilot_a/` regenerate the per-task files, and the analysis scripts below can then be run. This path has **not** been re-run end to end for this release; the stored outputs were produced earlier in the private working copy.

**C. Cannot currently be regenerated**
- Rankings for the original runs (not stored), per-run timestamps, graph-builder accuracy (no ground-truth call graph), and the exact upstream conversion pipeline of the Gemma GGUF.
- Model outputs may differ across hardware and `llama-cpp-python` builds; bit-identical Gemma outputs are not claimed.

**Analysis scripts and their inputs.** Each script below now checks its inputs first and exits with status 2 and an explanatory message when the per-task files are absent (as in this release), instead of failing with a bare file error. They remain in the release because they document how the reported checks were performed.

All commands run from the repository root with `uv run`. No GPU or paid API is needed to re-check reported numbers once the per-task files exist. Re-running the experiments themselves needs the commit-pinned repository snapshots (`manifests/repo_cache`, gitignored) and the Loc-Bench V1 raw data (`manifests/raw_data`, gitignored; licence unstated, not redistributed; provenance and sha256 in `manifests/data_manifest.json`).

## Configurations and seeds
- `configs/pilot_a*.yaml` (pilot, seeds 1–3, severities 0.0–0.75), `configs/evaluation.yaml`, `configs/holdout_{django,matplotlib,moto,sqlglot,sympy,ytdlp}.yaml` (holdout, one seed).
- Gate thresholds `coverage_floor = 0.6`, `isolated_ceiling = 0.5`, `anchor_floor = 0.1`, fixed in commit `1090b43`.
- Holdout pre-registration: `docs/HOLDOUT_PREREGISTRATION.md` (commit `f337085`). Not strictly blind; see `THREATS_TO_VALIDITY.md`.
- `node_omission` and `stale_rewire` seed `random.Random(seed)` directly; other operators derive sub-seeds with SHA-256 `_stable_seed`.

## Experiment entry points (`experiments/pilot_a/`)
`run_real_pilot.py` (pilot), `run_node_omission_experiment.py`, `run_coverage_floor_eval.py`, `run_weighted_gate_eval.py`, `run_gemma_v2.py` (needs the local Gemma 4 E2B GGUF; `manifests/gemma4_manifest.json`), plus the `stale_rewire` and holdout runners writing into `results/`. Raw outputs under `results/` are never edited.

## What is not reproducible from the repository alone
- Rankings were not stored for the original runs. Pseudo-node displacement in `repomap` is available only from the post hoc correction run (`experiments/pilot_a/run_repomap_correction.py CONFIG OUTDIR`; analysis `scripts/analyse_repomap_correction.py`).
- Per-run timestamps are not stored.
- Graph-builder accuracy has no ground truth.
- Loc-Bench V1 and the repository snapshots must be re-fetched from their sources.

## Interval convention
Primary intervals are exact repository-cluster enumeration. Stored 2,000-draw intervals remain in the results files and are a sensitivity analysis; differences are at most 0.016 (marginal), 0.005 (pilot paired) and 0.001 (holdout paired).
