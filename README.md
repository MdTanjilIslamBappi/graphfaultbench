# GraphFaultBench

GraphFaultBench is a small benchmark harness for studying how corruption of a statically built code
dependency graph affects issue-to-code localisation. It applies deterministic, severity-graded
corruption operators to graphs built from commit-pinned Python repositories, scores several
retrieval policies on [Loc-Bench V1](https://huggingface.co/datasets/czlll/Loc-Bench_V1) tasks, and
includes a small exploratory experiment with Gemma 4 E2B as a reranker. It accompanies a Kaggle
Gemma 4 Developer Agent Paper Track submission.

The principal write-up is `paper/manuscript.md` (the Kaggle Writeup text as submitted on 12 November 2026, with its reference list and Figure 1, `paper/figure1_degradation_and_reranker.png`;
three phrases that named individual Loc-Bench tasks are replaced here by counts and repository names, and
no result is changed). Treat the findings as exploratory: they rest on a pilot of six repositories, a
holdout of six further repositories, and one model. The limitations and threats to validity are
set out in the paper and in `submission/THREATS_TO_VALIDITY.md`.

## What the benchmark measures

It measures retrieval *given a graph*: how rankings change when a correct graph is degraded
synthetically. It does not measure graph-construction accuracy, and the correspondence between
the synthetic operators and real graph faults has not been validated.

## Repository layout

| Path | Contents |
|---|---|
| `src/gemma_research/data/` | typed graph and task structures, static-analysis graph builder, Loc-Bench task loader, snapshot fetching |
| `src/gemma_research/evidence/` | corruption operators (`perturb.py`), retrieval policies and the diagnostic gate (`retrieve.py`), Gemma reranker (`gemma_rerank.py`) |
| `src/gemma_research/metrics/` | Hit@k, MRR, strict accuracy, clustered bootstrap |
| `experiments/pilot_a/` | experiment runners |
| `configs/` | pilot, holdout and stale-rewire configurations (seeds, severities, repositories) |
| `scripts/` | analysis and audit scripts |
| `results/` | aggregate results only (see below) |
| `docs/` | pre-registrations and experiment log |
| `submission/` | revised paper and supporting audits |
| `manifests/` | provenance records (source URL, sha256) for the data and the Gemma checkpoint; no data |
| `LICENSES_AND_DATA_ACCESS.md` | licences, data access, and what is deliberately not included |

Where a document mentions an internal record (for example the decision log or status log), it is
marked "withheld from this release"; those records are not provided. Documents that name per-task
output files (`metrics.csv`, `rankings.jsonl`, `calls.jsonl` and similar) describe files that are
generated by the runners and are not included (see below).

## Data access (nothing third-party is redistributed)

- **Loc-Bench V1** must be downloaded separately from Hugging Face (`czlll/Loc-Bench_V1`, 560 rows;
  expected sha256 of the parquet file `8df0833c2c1276c5837aab923d489ab97d7654529abe759d0f59242c4978a662`,
  see `manifests/data_manifest.json`). Its dataset card states no licence.
- **Repository snapshots** are fetched at the commits recorded in each run's outputs.
- **Gemma 4 E2B** (4-bit GGUF) is obtained from Kaggle Models; the file and sha256 are in
  `manifests/gemma4_manifest.json`.

## What `results/` contains

Aggregate summaries, run manifests, exact-interval and paired-difference analyses, the `repomap`
correction analyses, and the synthetic framework-validation outputs. Per-task outputs
(`metrics.csv`, rankings, model calls, gold-resolution and graph reports) are **not** included,
because they carry Loc-Bench task identifiers, gold-derived hit flags or dataset-derived commit
mappings, and the dataset's redistribution terms are unstated. Earlier public commits of this
repository may still contain some of these files; they were not rewritten out of history.

**In short: the public artefacts reproduce the unit tests and the synthetic validation. They do not reproduce the paper's empirical results from raw inputs.**

## What can be reproduced

| Category | Content |
|---|---|
| From this release alone | the 68 unit tests; Ruff; the synthetic framework validation (`experiments/pilot_a/run_framework_validation.py`), whose outputs were regenerated byte-identically in a clean environment |
| Needs separately obtained data | all empirical results: Loc-Bench V1 (sha256 above), the pinned repository snapshots and, for the reranker, the Gemma 4 E2B GGUF. The runners regenerate the per-task files; this path has **not** been re-run end to end for this release |
| Cannot currently be regenerated | rankings of the original runs (not stored), per-run timestamps, graph-builder accuracy, the GGUF's conversion pipeline |

The analysis scripts in `scripts/` read the per-task files. On this release they stop with exit
status 2 and a message naming the missing inputs. **The paper's empirical results have not been
reproduced from raw inputs for this release**; the files in `results/analysis/` are the stored,
as-run records. Details: `submission/REPRODUCIBILITY_GUIDE.md`.

## Tests and set-up

```bash
uv sync --extra dev
uv run pytest -q     # 68 tests, CPU only, under a few seconds
uv run ruff check .
```

`llama-cpp-python` is a declared dependency (used only by the Gemma runner) and may need to be
built from source if no wheel is available for your platform.
